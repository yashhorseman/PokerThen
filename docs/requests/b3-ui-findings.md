# B3 findings for the UI agents (apps/web) - written by Phase B3

(Items 1, 2, 3 and 5 were fixed by B3, see docs/status/B3.md; 4 is left as a note.)

1. Header ante text: research 08 evidence `closing/f2.png` shows `NLH ~ 10 / 20 (A:5)` (no space after the colon). The client renders `(A: 5)`. (SPEC 4.2 text says `(A: ante)`; the screenshot wins.)
2. Time bank auto-activation: `apps/web/src/actions/ActionArea.tsx` sends `ATB` at the START of every turn (E7: ATB goes out within ~1.5 s with a 4 s limit), so every turn shows `EXTRA TIME ACTIVATED` from the first moment. Research 06/08: the button reads `ACTIVATE EXTRA TIME (Ns)` while the decision clock runs and flips to `EXTRA TIME ACTIVATED` only when the decision limit expires (auto-activate pref on); with the pref off the server folds at the limit and the bank is untouched. Fix: auto-send ATB only once `serverNow() >= turn.deadlineNoBank` (engine tolerates it until limit + 1.5 s grace).
3. Rebuy owner dialog (`apps/web/src/menus/QuickAcceptHost.tsx` RebuyDialogs): the dismissal key is `app-${req.playerId}`, so after the owner approved/denied Bob once, a SECOND rebuy request by the same player (later hand) never opens the dialog (state `dismissed` stays set). Include the hand number (`app-${vm.handNumber}-${playerId}`). The e2e works around it by reloading the owner page (b3-06 prints KNOWN-DIFF).
4. Rebuy prompt CANCEL (busted player) only dismisses the modal locally; no command is sent, the player keeps the seat until the 20 s window ends. Research 08 d: cancel / no confirmation => `The player Kim quits the game with a stack of 0.` (timing of the cancel case unobserved: ambiguous, left as is).
5. Rebuy dialogs share one `val` state that is never reset: Bob's second prompt keeps the text typed earlier (and the owner's approve value leaks into the next prompt), so typing appends (`1000` + `800` -> `1000800` -> server rejects). Reset `val` when the dialog key changes. (e2e selects the field text before typing.)
