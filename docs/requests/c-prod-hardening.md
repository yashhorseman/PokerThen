# c-prod-hardening - fail-open production configuration (MEDIUM/LOW; two items APPLIED, three proposed)
1. APPLIED `env.ts`: App Service always sets WEBSITE_SITE_NAME. With NODE_ENV forgotten the server ran as "dev": public default SESSION_SECRET `dev-secret-not-for-production` (anyone can compute player ids), DEV_ORIGINS, DEV_FIXED_DECKS (scripted decks) honoured. Now `isProd = NODE_ENV==="production" || (onAzure && NODE_ENV!=="development")`, so SESSION_SECRET is required and DEV_* ignored on Azure. Test: `s02-cookies.mjs`; `server.test.ts` updated.
   `-  const isProd = src.NODE_ENV === "production";`  `+  const isProd = src.NODE_ENV === "production" || (onAzure && src.NODE_ENV !== "development");`
2. APPLIED `router.ts`: `Strict-Transport-Security: max-age=15552000` in production.
3. PROPOSED minimum SESSION_SECRET length (a 1-character secret is accepted): in `loadEnv` `if (isProd && src.SESSION_SECRET!.length < 16) throw new Error("SESSION_SECRET must be at least 16 characters")` (the existing unit test uses `"s"`; change it to a 16+ char value). Do NOT rotate the secret after launch: all owners/players are orphaned (measured).
4. PROPOSED Node timeouts (half-sent HTTP headers stayed open 80 s; Azure's front end shields this, still cheap): after `createServer`: `server.headersTimeout = 20_000; server.requestTimeout = 30_000;`.
5. PROPOSED canonical host: the Origin check is `Origin == scheme://<Host header>` (self-referential, so a DNS-rebinding page whose Host is attacker-controlled passes). On Azure the front end only routes the app's own host names, so impact is nil there; for self-hosting set `ALLOWED_ORIGINS` and, in production, compare against `WEBSITE_HOSTNAME` instead of the request Host.
