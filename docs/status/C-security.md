# Phase C - security + fairness review (2026-10-26)

Method: every check runs against the REAL built server (`esbuild` bundle of `apps/server/src/main.ts`, started as a child process on a temp port and temp `DATA_DIR`, killed afterwards) with the real engine and real client where relevant. Scripts: `tests/security/s01..s09*.mjs`, runner `node tests/security/run.mjs` (about 15 min; `PT_ROOT` audits a frozen copy, `PT_PUBLIC` = built web dir). Each script prints PASS / FAIL / DEFECT / INFO; DEFECT = a secure behaviour the code does not (yet) have and names the `docs/requests/c-*.md` that fixes it. An in-process probe (`lib/pollution-probe.cjs`, preloaded into the server) watches the built-in prototypes for pollution.

## What passed (evidence in the scripts)
1. Origin (s01, 43 checks): WS upgrade and unsafe POSTs reject missing / `null` / foreign / other-port / suffix / https-on-http Origins; `Sec-Fetch-Site` fallback only for same-origin; X-Forwarded-Host/Proto ignored unless `TRUST_PROXY`/Azure; allow-list exact; DEV_ORIGINS off in production; PUT/DELETE/PATCH 405; no CORS grants. Note: expected origin is derived from the request Host (self-referential; harmless on Azure, see c-prod-hardening 5).
2. Cookies (s02): `HttpOnly; SameSite=Lax; Path=/; Max-Age`, no Domain, 50 URL-safe chars; `Secure` when `X-Forwarded-Proto: https` behind a trusted proxy and always in production; not minted for healthz/static/404; malformed cookies replaced. Ids are HMAC(secret, token): public ids, padded ids, malformed cookies and 20k random tokens never authenticate as another player. Production refuses missing/empty SESSION_SECRET; secret and tokens never appear in logs or bodies. Rotating the secret orphans every owner (measured): never rotate.
3. Authorization (s03): 10 owner-only POSTs + `GET players/:pid` x 6 caller classes (anonymous, fresh token, watcher, pending guest, seated player, owner of another table) = 66/66 refusals with state unchanged; owner-only WS actions (UP UR TSG NH RS) ignored for non-owners; no cross-table IDOR; ownership transfer moves the rights.
4. Input (s04): 16 KB body limit (413), 5 MB and chunked bodies refused, oversize headers/URLs refused, hostile JSON never 5xx except the update_game items above, `__proto__`/`constructor` keys in bodies, WS and nested config: no pollution in the server process; numeric edge values (negative, fractional, 1e21, MAX_SAFE+, strings, null) rejected or clamped, stacks stay finite integers; WS 4096 B ok / 4097 B -> 1009, 1 MB -> 1009, garbage and binary frames ignored; chat 100 code points (101 dropped, control chars replaced); HTML in chat/nicknames is inert in the real client (headless Chrome: 8/8 payloads shown as text, no `<img>`/script injected, no CSP violation).
5. Limits (s05): 20 sockets/IP (4429), 40 msgs/2 s (4430), 120 POST/10 s, 10 `/new-game`/min, 30 log/10 s (429); unresponsive WS client terminated after 26 s. Residual: GET endpoints other than log/CSV are unthrottled; half-sent HTTP headers stay open 80 s (Azure's front end shields this, c-prod-hardening 4).
6. Hidden info (s06): 20 tables x 4 bots + a watcher, 143 real hands (all-in, run-it-twice votes, rabbit hunts, folds, shows, show-all on and off), 13 235 reconstructed frames, 2 430 HTTP bodies (log_v3, CSVs, ledger, configs, fairness, error bodies, healthz). Ground truth (deck, master salt, hole cards) read from state.json. Result: no unentitled card, no master salt, no per-card salt (exposed or not) in any WS message; 'Your hand is' only for the owner of the cards; board equals the committed deck positions; burn positions never revealed; reveal == cards exposed in the public log; DATA_DIR files all 0600/0700; state.json never served (traversal with `..`, `%2e%2e`, `%252e`, `\`, NUL, `//` all 404).
7. Fairness (s07, s08): 100 000 production-entropy shuffles: per-position chi-square (df 51) worst 76.7, min p 0.012 (Bonferroni threshold 0.0005), per-card and first-pair uniform, fixed points 100 076 (expected 100 000 +- 313); rejection sampling exact (limit-1 accepted, limit and 2^32-1 redrawn, 48 rejected values for n=52, short entropy refused); 15 tamper kinds (card, salt, proof, truncated proof, root, prevCommitment, commitment, index, index 52, duplicate index, handNumber, gameId, handId, usage, forged log commitment / board / missing / late commitment line) all FAIL on the web verifier and the CLI (except duplicate-card, finding 9); chain breaks at the next hand when an earlier commitment changes; commitments are table-bound. Server: for every first hole-card frame the commit row, `state.json` and the commitment log line were already durable and ordered; the public endpoint never showed a reveal before the end of the result window.
8. Crash recovery (s08): 10 SIGKILL cycles at random points mid-hand with bots playing: hand numbers never regress, no log line visible before a crash lost or altered, no duplicate/torn lines (client view and disk), chips conserved (3000) at every restart, the running hand keeps the same commitment and hole cards (no re-shuffle), commitments and chain intact, every `update_game` acked 200 survived a SIGKILL sent right after the ack. Disk-full style (RLIMIT_FSIZE): see finding 2 (fixed).
9. Headers (s09): nosniff, `Referrer-Policy: same-origin`, CSP (`default-src 'self'`, frame-ancestors/object-src none, base/form self, no unsafe-eval or inline script, production `connect-src 'self' wss://<host>` only) on HTML, assets, API, 404/403/302; API `no-store`, HTML `no-cache`, hashed assets immutable; no source maps, no dotfiles, no X-Powered-By. Engine: no `Math.random` / `Date.now` / entropy outside `ctx.entropy` (`hash.ts` uses node:crypto only for SHA-256); `Math.random` exists only for client reconnect jitter. `npm audit`: 15 findings, all in dev tooling (vitest/tinypool, esbuild dev server, puppeteer extract-zip, basic-ftp) except `zod <4.6.6` (memory exhaustion on oversized constrained collections): runtime dependency, not exploitable here (bodies are capped at 16 KB / 4 KB and no schema validates collections); list only, no upgrade made.

## Honest limits / not verified
- Azure behaviour (appended `X-Forwarded-For`, whether the front end overwrites `X-Forwarded-Host`) was not observed: needs a deploy, which was not allowed. The XFF fix is correct for append and overwrite.
- The chain protects history only if someone holds an earlier commitment (log line / screenshot); an operator who rewrites everything from genesis is not detectable. Uniformity of the shuffle is statistical evidence (above) plus the open code; the commitment proves order was fixed before play.
- Rabbit cards are published in the public fairness reveal after a hunter requests them although only hunters see them in frames (owner-approved design in FAIRNESS-MERKLE).
- Rate-limit numbers are the U-N1 placeholders; presence still causes one fsync'd state write per connect (c-ws-flood follow-up).
- Not tested: real phone, TLS termination itself, Azure Files fsync latency, multi-instance (not supported).
- Unrelated e2e note: `b3-11-blind-levels.mjs` hard-codes who posts the small blind in a heads-up hand with a random first dealer (fails about half of the runs); every other scenario passed after these fixes.
